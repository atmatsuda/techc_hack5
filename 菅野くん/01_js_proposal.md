# [AI翻訳チャット＋通話アプリ（仮）] JavaScript動作・UIロジック要望書

## 1. 画面挙動コンセプト・全体の世界観
言葉の壁を越えて世界中の人と繋がるこのアプリでは、「メッセージが相手に届く」という体験そのものを、紙飛行機が飛んでいくアニメーションで視覚化する。処理待ちのフリーズ感や連打による誤操作を徹底的に排除し、ユーザーが直感的に「今何が起きているか」を理解できる、テンポの良い操作感を提供する。言語が異なるユーザー同士でも、アイコンやアニメーションといった「言葉に頼らない」表現で状態が伝わることを重視する。

## 2. ターゲットユーザーとJavaScriptの提供価値
- **操作における画面上のペイン：** 送信ボタンの連打によるサーバー負荷・誤送信、既読確認の不統一、画面切り替えの不具合、処理中のフリーズ感、ボタンサイズが小さく反応しにくいことによる誤操作・ストレス
- **JavaScriptが提供する独自の体験：** 送信直後に即座にメッセージを表示する体感速度の速さ（Optimistic UI）、翻訳中であることが一目でわかる地球儀アニメーション、通話画面への物理的な移動を感じさせるスライド演出により、通信環境に左右されずストレスのない操作感を実現する

## 3. 主要JavaScript動作・イベント要件
- **チャット送信アクション：**
  - 入力欄が空の場合、送信ボタンは非活性（薄いグレー）状態にし、押下自体を無効化する
  - 入力欄に文字がある場合のみ送信ボタンを活性化する
  - 送信ボタン押下時、サーバーの応答を待たずに即座に入力値を取得し、自分のチャットバブルとして画面に追加する（楽観的UI更新）
  - メッセージ追加と同時に入力欄をクリアする
  - 送信中は0.5〜1秒程度ボタンをグレーアウトし、紙飛行機アニメーションが終わり次第、次の入力を受け付ける状態に戻す（サーバー応答を待たない）

- **翻訳/お助け機能アクション：**
  - 相手からメッセージが届くと、そのチャットバブル内に地球儀アイコンを表示し、翻訳処理中であることを示す
  - 地球儀アイコンは回転アニメーションで表示し、翻訳結果が返り次第、アイコンを翻訳済みテキストに差し替える
  - メッセージごとに個別で処理状態を管理し、複数メッセージが同時に届いても混同しないようにする

- **通話開始・切断アクション：**
  - 通話ボタン押下時、チャット画面全体がスライドして消え、通話中画面（モック）がスライドインする
  - スライドアニメーション中は画面全体を一時的にロックし、他のボタン操作を受け付けない
  - アニメーション完了後にロックを解除する

## 4. 画面の動的挙動（インタラクション・アニメーション要件）
- **送信完了の演出：** 送信ボタン押下時、入力欄からメッセージが紙飛行機のような軌道で画面外（右上方向）へ飛んでいき、消える演出を行う
- **ローディング/処理中表示の動き：** 翻訳中は該当メッセージのチャットバブル内で地球儀アイコンが回転し続ける。処理完了と同時にアイコンを非表示にし、翻訳結果テキストへ切り替える
- **画面切り替え時のスライド効果：** チャット⇄通話中画面の切り替えは、現在の画面が横方向にスライドアウトし、次の画面がスライドインする形で行う。切り替え中は誤操作防止のため全体を一時ロックする
- **エラー表示の動き：** 送信失敗時は該当メッセージの横に赤い「！」マークを表示し、タップすることで再送信処理をトリガーできるようにする

## 5. 次のステップ（実装に向けたエンジニアへの伝達事項）
- **Geminiへのプロンプト方針：** 「楽観的UI更新（Optimistic UI）」という考え方を明示した上で、送信処理・エラー時のロールバック処理（！マーク表示＋再送信関数）をセットでコード生成依頼すると実装漏れが防げる
- **西野くん（画面デザイン担当）への連携事項：** ボタンサイズは視認性・操作性を重視し、最低でも44px四方程度のタップ領域を確保してほしい旨を伝える。また、紙飛行機・地球儀アイコンのデザイン素材（SVGなど）が必要になるため、早めにすり合わせたい
- **川井田くん（Python担当）への連携事項：** フロント側は「送信ボタン押下→即座に表示→裏側で送信処理」という順序で動くため、送信失敗時にフロントへエラーを正しく返すAPIレスポンス設計をお願いしたい。また、翻訳処理の完了通知（WebSocketやポーリングなど）のタイミングも早めに擦り合わせたい
