# [AI翻訳チャット＋通話アプリ（仮）] JavaScript・UIロジック要件定義書

## 1. システム概要（JavaScript動作）
- **目的・動作コンセプト：** 言葉の壁を越えて世界中の人と繋がるチャット＋通話アプリ。メッセージの送受信・翻訳・通話への画面遷移を、疑似モックアップとしてJavaScriptのタイマーや配列操作で再現する。加えて、利用者が自分の英語表現をより深く理解できるよう、文法解説・フレーズ対応関係の可視化・表現の「型」一覧・履歴アーカイブの4つの学習支援機能をJS側のロジックとして実装する。
- **動作環境：** ブラウザ環境（URL: `http://localhost:[各自のポート]/[各自の半角英数字フォルダ名]/index.html` または Live Server環境）

## 2. JavaScript機能要件（今回実装する動作）

### 基本機能（チャット・通話・翻訳）
- [ ] `addChatBubble(text, sender)`：メッセージをチャットエリアのDOMに追加する（難易度：レベル2）
- [ ] `playFlyAnimation(element)`：紙飛行機アニメーションのクラス着脱を行う汎用アニメーション制御関数（難易度：レベル2〜3）
- [ ] `sendMessage()`：入力値取得→`addChatBubble`呼び出し→`playFlyAnimation`呼び出し→`setTimeout`によるボタンの活性/非活性制御を統括する（難易度：レベル3）
- [ ] 入力欄が空の場合、送信ボタンを非活性（グレーアウト）にするイベントリスナー（難易度：レベル1）
- [ ] 受信メッセージの地球儀アイコン回転表示→翻訳完了後にテキストへ差し替える処理（メッセージごとに個別管理）（難易度：レベル3）
- [ ] 通話ボタン押下時のチャット⇄通話画面スライド切り替え＋アニメーション中の全体ロック（難易度：レベル2〜3）
- [ ] 送信失敗時の「！」マーク表示＋クリックによる再送信トリガー（難易度：レベル2〜3）

### 追加機能①：アーカイブ機能
- [ ] `#archive-save-btn`クリック時、`chatHistory`配列を`localStorage.setItem()`で保存（難易度：レベル2）
- [ ] `#archive-load-btn`クリック時、`localStorage.getItem()`で取得した履歴データで`chatHistory`を上書き→チャットエリアを再描画（難易度：レベル2〜3）

### 追加機能②：文法解説の表示
- [ ] チャットバブル下に`hidden`クラス付きで用意した`.grammar-note`エリアを、アイコンクリックで`classList.toggle('hidden')`により開閉する`toggleGrammarNote(element)`（難易度：レベル2）

### 追加機能③：対応関係の可視化（ハイライト＋ポップアップ）
- [ ] `phraseMap`に登録済みのフレーズ文字列を、翻訳結果テキストから単純一致検索し、`.phrase`（`data-phrase-id`付き）の`<span>`へ動的に置き換える処理（難易度：レベル3〜4）
- [ ] `.phrase`クリック時、`getBoundingClientRect()`で位置取得→`#tooltip`要素（使い回し）の`style.top`／`style.left`を固定オフセットで更新し表示、外側クリックで非表示にする処理（難易度：レベル3〜4）

### 追加機能④：表現の「型」一覧機能
- [ ] `.tab-btn`（`data-axis`属性）クリック時、アクティブタブの`classList`切り替え（難易度：レベル2）
- [ ] 選択中の軸に応じた固定配列（例：`sceneGroups`）を`forEach`し、`expressionData`を`filter()`してグルーピング→見出し＋リストを`#expression-list`に動的生成する処理（難易度：レベル3）

## 3. ロジック品質・エラーハンドリング要件
- **JavaScript制御・実装方針詳細：**
  - ① 空文字送信やスペース連打の制御：入力値を`trim()`した上で空文字なら送信処理自体を実行しない（送信ボタンの非活性化と二重にガードする）
  - ② ユーザー入力テキストの安全なDOM追加処理：`innerHTML`は使用せず、`textContent`または`createTextNode`を用いてXSSを防止する（翻訳結果・文法解説・フレーズハイライトの`<span>`生成部分も、テキスト部分は`textContent`ベースで組み立てる）
  - ③ チャットエリアの自動スクロール制御：`addChatBubble`実行後、`chatArea.scrollTop = chatArea.scrollHeight`により最新メッセージまで自動スクロールする
  - ④ 擬似通話中の経過タイマー：通話画面表示と同時に`setInterval`を1秒ごとに実行し、`00:00`形式でカウントアップ表示。通話終了時に`clearInterval`で確実に停止する
- **通信・エラー時の画面表示方針：** 送信失敗時（疑似的なランダム失敗判定等）はコンソールエラーで処理を止めず、該当メッセージ横に「！」マークを表示し、クリックで再送信関数を再実行できるようにする。アーカイブ読み込み時に`localStorage`にデータが存在しない場合も、エラーで止めず「保存データがありません」等の安全な文言を画面に表示する

## 4. 今回スコープアウト（完全に対象外にした）機能
- **翻訳API・音声通話のリアルタイム通信（レベル5）：** 本物のDeepL等翻訳APIとの直接通信、および本物のWebRTCによる双方向音声ストリームは行わない。すべてJS内のダミーデータと`setTimeout`による疑似応答で表現する
- **対応関係可視化のツールチップにおける高度な位置計算：** 画面端でのはみ出し防止など複雑な座標補正ロジックは行わず、「クリックされたフレーズの直下に固定オフセットで表示」というシンプルなルールに限定する（開発期間内完成を優先）
- **フレーズハイライトの自然言語処理：** 形態素解析や曖昧一致による動的なフレーズ検出は行わず、`phraseMap`にあらかじめ登録した文字列との単純一致検索のみで実装する
- **表現の「型」一覧の複数条件AND絞り込み：** 「フォーマル度：高」×「感情：冷静」のような複数フィルターの同時組み合わせは行わず、1軸ずつのタブ切り替えのみとする
- **表現の「型」一覧の動的グルーピング：** データから未知の値を自動検出してグループ見出しを生成するロジックは行わず、軸ごとに固定配列で見出しを決め打ちする
- **アーカイブ機能の自動保存：** メッセージ送受信のたびに自動保存する設計は行わず、`#archive-save-btn`のクリック時にのみ明示的に保存する
